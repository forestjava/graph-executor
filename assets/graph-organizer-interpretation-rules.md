# Правила верхнего уровня

Разбор реплики пользователя в четыре шага:

**1. Извлечь сущности** — найти все `PREFIX-NUMBER`; даты и относительные сроки («до пятницы», «через неделю»); людей и роли (`reasonDetail`: «Рома», «Первов»); ресурсы запроса (время, концентрация, прерываемость).

**2. Определить намерение** — рекомендация · фиксация · triage выборка (чем заняться сейчас) · задать/обновить Priority · задать/обновить Urgency · задать/обновить Effort · декомпозиция / блокер · относительный порядок (`RANKS_ABOVE`) · только чтение контекста.

**3. Сопоставить с осями** — каждый смысл ровно на одну ось; не смешивать важность, срок и объём усилий. При неоднозначности (snooze vs deadline, hard vs soft) — уточнить у пользователя.

**4. Сформулировать команду** — одна или несколько декларативных инструкций для навыка[/graph-executor-command-interpreter](skill://graph-executor-command-interpreter) с id work-узлов и явными значениями свойств.

## Canonical phrase → axis

| Формулировка | Ось / операция |
|--------------|----------------|
| важно / критично / стратегически / приоритет | `HAS_PRIORITY` → `level` |
| не срочно / когда-нибудь / низкий приоритет | `HAS_PRIORITY` → `level: low` или `normal` |
| срочно / горит / дедлайн / до \<дата\> | `HAS_URGENCY` → `dueTo`, `reason: deadline` |
| выполнить \<окно дат\> / в этот период | `HAS_URGENCY` → `dueFrom` + `dueTo`, `reason: window` |
| отложи / не беспокоить / snooze / вернуться после | `HAS_URGENCY` → `dueFrom`, `reason: snooze` |
| жду / waiting / жду ответа \<кто\> | `HAS_URGENCY` → `dueFrom`, `reason: waiting`, `reasonDetail` |
| обещал / commitment | `HAS_URGENCY` → `dueTo` (+ опц. `dueFrom`), `reason: commitment`, `reasonDetail` |
| проверю у / delegation / делегировал | `HAS_URGENCY` → `dueFrom`, `reason: delegation`, `reasonDetail` |
| сознательно отложил / загружен | `HAS_URGENCY` → `dueFrom`, `reason: load` |
| hard deadline / нарушение обязательства | Urgency → `mode: hard` |
| ~N минут/часов / deep work / лёгкое / прерывается | `HAS_EFFORT` → `size`, `duration*`, `concentration`, `interruptible` |
| сначала X / blocked by / зависит от / жду Y | `DEPENDS_ON` (+ при необходимости свой Urgency/Effort на блокере) |
| X важнее/срочнее/тяжелее Y | `RANKS_ABOVE` между соответствующими Priority / Urgency / Effort |
| что делать / чем заняться / что успею / triage | рекомендация, чтение |
| повторяется / каждую неделю / каждый месяц / серия | записать `Series` и слоты |
| перенеси этот экземпляр / сдвинь эту дату | записать новые `dueFrom` и `dueTo`, ключ сохранить |
| сделал / готово / закрыл | `status: done` |
| дальше / следующий шаг | закрыть названную задачу и создать новую |
| заблокировано / жду сначала | `DEPENDS_ON` на названный блокер |
| вернулся / отметь / перенеси срок | фиксация |

## Canonical phrase → Urgency `reason`

| reason | Когда | Типичные поля |
|--------|-------|---------------|
| `window` | выполнить в интервале | `dueFrom`, `dueTo` |
| `deadline` | сдать к дате | `dueTo`; опц. `mode: hard` |
| `snooze` | отложить, снять с фокуса до даты | только `dueFrom` |
| `waiting` | жду внешнее событие | `dueFrom`, `reasonDetail` |
| `commitment` | обещание | `dueTo` (+ опц. `dueFrom`), `reasonDetail` |
| `delegation` | проверить у делегата | `dueFrom`, `reasonDetail` |
| `load` | отложено из‑за загрузки | `dueFrom` |

Snooze, waiting, check-back, delegation-follow-up — все через **`dueFrom`** с разным `reason`.

## Рекомендация

Окно: интервал, названный в реплике. Если интервала нет, агент спрашивает его и выборку строит после ответа. Свободное время, концентрация и прерываемость берутся из реплики. Если свободное время не названо, фильтр по длительности не применяется.

Агент четырьмя чтениями собирает: события окна, обязательства, исполнимые шаги, открытые задачи с `dueTo` раньше текущего момента. Один и тот же `id` остаётся в одном пункте ответа. Открытые задачи с заполненным `seriesId` входят в обязательства, в том числе если их `localStart` раньше окна.

Исполнимый шаг: живая задача без открытой задачи на другом конце её `DEPENDS_ON`. Для заблокированной задачи в список попадает такой открытый шаг дальше по цепочке. Если назван контекст, чтения шагов ограничены его `prefix`, и в расчёт берётся весь этот кластер.

Событие окна остаётся в списке событий, пока его задачи с `scheduleRole: preparation` открыты. Ответ прямо говорит, что подготовка открыта.

Подготовка и восстановление: задачи с `scheduleRole` `preparation` и `recovery`, чьё окно пересекает названный период. Срок подготовки считается от `dueFrom` вехи назад на названную длительность блокера. У параллельных блокеров берётся самая большая названная длительность. Если у ветки `certainty: unknown`, дата этой ветки в ответе названа неизвестной.

Если свободное время названо, агент оставляет шаги, которые в него укладываются. Занятые интервалы событий и шагов с `kind` `travel` и `preparation` сливаются. Пересечение входит в сумму один раз. Шаг с `interruptible: false` требует один цельный интервал. Шаг с `interruptible: true` может занять несколько интервалов. `kind: waiting` свободное время не занимает. Между соседними выбранными шагами с разным `prefix` добавляется шаг `kind: context_switch`, если у него названа длительность. В сумму входят выбранные шаги. Если у родителя `includesChildren: true`, его длительность поверх выбранных детей не прибавляется. Шаг с неизвестной длительностью в эту сумму не входит.

После фиксации сделанной работы следующая рекомендация заново раскладывает только ещё открытые шаги. Если два обязательства попадают на одно и то же время, ответ называет оба `id` и оба срока и записывает срок того, который пользователь выбрал.

Ранжирование подходящих шагов: сначала `reason` `commitment` и `deadline`, затем более ранний `dueTo`, затем `Priority.level` в порядке `critical`, `high`, `normal`, `low`, затем ребро `RANKS_ABOVE`. Ответ называет несколько конкретных занятий. У шага с `reason` `commitment` или `deadline` ответ содержит слово «обязательство».

Слоты серии агент считает сам и передаёт массивом `$slots`. Дата идёт от `validFrom` до `validTo`. `daily`: шаг в `interval` дней. `weekly`: дни из `byWeekday` в каждой `interval`-й неделе, первая неделя содержит `validFrom`. `monthly`: число `byMonthDay`. Если в месяце такого числа нет, слота этого месяца нет. `yearly`: месяц `validFrom` и день `byMonthDay` либо день `validFrom`, каждые `interval` лет. Если дня в году нет, слота этого года нет. `localStart` собирается из даты и `localTime` как `YYYY-MM-DDTHH:mm:ss`. Ключ: `seriesId + ':' + localStart`. В `datetime()` агент передаёт эту локальную метку со смещением `timeZone` серии. Конец слота равен началу плюс названная длительность. Если длительность не названа, конец равен началу.

Перед записью агент читает уже существующие `occurrenceKey` этой серии. Для них он передаёт уже записанный `id`. Новые `id` получают только новые ключи: префикс: часть `seriesId` до дефиса, номера идут от текущего максимума этого префикса. Пока пользователь не просит сохранить график, агент показывает посчитанные слоты и `MERGE` не вызывает. Сохранённый слот в ответе назван сохранённым, посчитанный и ещё не записанный назван посчитанным.

Каждая запись: один `execute`. Сразу после неё отдельное чтение подтверждает `id` и `occurrenceKey`.

Длинный список агент дочитывает тем же запросом с `SKIP $shown`, где `$shown`: число уже показанных `id`.

Фоновый планировщик и канал доставки в текстах отсутствуют. Ответ описывает записанные узлы и следующую выборку.

## Фиксация

Пользователь называет сделанное, блокер или новый срок. Агент переписывает названные свойства. Для «готово» ставит `status: done`. Для следующего шага закрывает названную задачу и создаёт новую с `id`, `prefix`, `title`, `status: open`, пустым `summary`. Для переноса пишет только названные `dueFrom` и `dueTo`. Затем читает затронутые узлы и повторяет в ответе записанные значения.

## Ресурсы запроса (из диалога с пользователем)

| Формулировка | Фильтр triage |
|--------------|---------------|
| есть N минут / час / полдня | `durationValue`, `durationUnit` ≤ N |
| до обеда / до встречи | `duration` + `NOW()` |
| только лёгкое / без deep work | `concentration` ≠ `deep` |
| могу прерываться | `interruptible: true` |
| между встречами / в дороге | малый `size`, `interruptible: true` |

Если ресурсы не названы — triage по важности и срочности; Effort — как подсказка.
